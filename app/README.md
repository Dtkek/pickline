# Pickline

Локальное приложение для Dota 2: подсказывает, кого брать против вражеского драфта,
показывает мету по героям и разбирает профессиональные матчи.

## Запуск

**Windows, без Python:** со страницы
<https://github.com/Dtkek/pickline/releases/tag/latest> скачать
`pickline-setup.exe` и установить — в профиль пользователя, без прав
администратора, с ярлыками в «Пуске» и на рабочем столе; удаляется через
«Программы и компоненты». Установленные файлы не несут метку «скачано из
интернета», поэтому при запуске Windows ничего не спрашивает; SmartScreen
покажется один раз — на сам установщик (неподписанный). Второй вариант —
`pickline.exe` без установки: один файл, но у скачанного файла есть метка,
и Windows будет переспрашивать при каждом запуске, пока не снять её
(правый клик → Свойства → «Разблокировать»).

Внутри уже всё: Python, OpenCV, numpy, pywebview. Пересобирается
автоматически при каждом изменении в `main` (GitHub Actions,
`.github/workflows/build-windows.yml`, установщик — `installer/pickline.iss`).
При запуске exe распаковывается во временную папку — первые секунды уходят
на это. Свои данные (кэш, портреты героев, хранилище окна, обновлённые
снимки) приложение держит в `%LOCALAPPDATA%\Pickline`, поэтому обновление
их не стирает; лог `pickline.log` и файл токена STRATZ — рядом с exe. Где
что лежит, решает `app/paths.py`.

**Окно, а не вкладка.** Приложение открывается в собственном окне
(pywebview: на Windows — встроенный WebView2, на macOS — WebKit), браузер
не нужен. Сервер при этом работает как раньше, просто его не видно;
закрыли окно — приложение остановилось. Без пакета pywebview приложение
открывается во вкладке браузера, это не ошибка. Ключи: `--browser` —
принудительно в браузер, `--on-top` — окно поверх остальных (держать над
Dota в оконном режиме; переключателя на ходу нет: на Windows он вешал
приложение), `--no-browser` — только сервер без интерфейса. Чтобы exe
всегда запускался поверх окон, добавьте `--on-top` в поле «Объект» ярлыка.

**Без консоли.** Exe собран без чёрного окна консоли. Всё, что раньше
писалось в консоль, пишется в `pickline.log` рядом с exe
(перезаписывается на каждом запуске). Если приложение упало — окно
сообщения с текстом ошибки; если окно не открылось и сработал откат в
браузер — окно сообщения с адресом и кнопкой ОК, которая останавливает
приложение. Ярлык на рабочий стол: правый клик по exe → «Отправить» →
«Рабочий стол (создать ярлык)», иконка подхватится сама.

**Windows, из исходников:** двойной клик по `start.bat` в корне проекта. Скрипт сам найдёт
Python, при первом запуске поставит пакеты для чтения экрана и откроет браузер.
Должно открыться чёрное окно консоли.

Если вместо консоли открывается VS Code или «Блокнот» — это не ошибка скрипта,
а привязка расширения `.bat` в Windows: файл открывается на редактирование
вместо запуска. Любой из способов ниже решает задачу:

- Shift + правый клик по пустому месту в папке → «Открыть окно PowerShell здесь»,
  затем набрать `.\start.bat`
- правый клик по `start.bat` → «Открыть с помощью» → «Выбрать другое приложение»
  → `C:\Windows\System32\cmd.exe` → поставить галочку «Всегда»
- создать ярлык: правый клик → «Создать ярлык», в свойствах ярлыка в поле
  «Объект» написать `cmd /c "полный\путь\start.bat"`

**macOS и Linux:**

```
python3 app/server.py
```

Откроется окно приложения (если стоит pywebview, `pip install -r
app/requirements-window.txt`) или браузер на `http://127.0.0.1:8777`.
Основная часть работает на одной стандартной библиотеке Python 3; пакеты
нужны только для чтения экрана и собственного окна.

Полезные ключи:

```
python3 app/server.py --port 9000      # другой порт
python3 app/server.py --browser        # во вкладке браузера, а не в окне
python3 app/server.py --on-top         # окно сразу поверх остальных
python3 app/server.py --no-browser     # только сервер, без интерфейса
```

Сбросить кэш данных: открыть `http://127.0.0.1:8777/api/cache/clear`.

## Если что-то не работает

Первым делом — `pickline.log` рядом с exe: там всё, что
приложение сообщало при запуске, и текст ошибки, если что-то упало.

**Окно не открывается, в логе `Failed to resolve Python.Runtime.Loader.Initialize`.**
У этой ошибки (HRESULT `0x80131515`) две причины, и приложение снимает обе
само при запуске:

- **Метка «скачано из интернета».** Windows метит скачанный файл (поток
  `Zone.Identifier`), а .NET Framework отказывается грузить помеченную
  сборку. С одним exe это почти не встречается: DLL распаковываются во
  временную папку уже без метки. На всякий случай приложение всё равно
  снимает метку со своих распакованных файлов при запуске; вручную —
  правый клик по exe → Свойства → «Разблокировать».
- **Кириллица в пути** (обычно «Рабочий стол»): pythonnet передаёт путь к
  `Python.Runtime.dll` в .NET как ANSI-строку, и она «не находится».
  Приложение копирует папку `runtime` pythonnet в первую папку с
  ASCII-путём (`%TEMP%\pickline\pythonnet`) и берёт DLL оттуда.
  Если такой папки не нашлось (кириллица и в имени пользователя) —
  открывается в браузере и просит перенести папку, например, в
  `C:\pickline`.

Если окно так и не открылось, приложение не падает: интерфейс полностью
работает во вкладке браузера, окно — удобство, а не функция.

Запустите диагностику — она проверяет каждое звено по отдельности и говорит,
где именно затык: версия Python, пакеты, DNS, доступ к `api.opendota.com`
двумя разными способами, CDN с портретами, файлы приложения, занятость порта.

**Windows:** `diagnose.bat`
**macOS и Linux:** `python3 app/tools/diagnose.py`

Самая частая причина пустого интерфейса — нет доступа к `api.opendota.com`.
Совсем без него приложение работает на снимках из репозитория (подбор,
турниры, общая сборка и прокачка), но лента про-матчей и сборка против
конкретного драфта появляются только с живой базой.

**«OpenDota не отвечает (SSL/TLS-соединение не установилось)».** Канал до
`api.opendota.com` (он за Cloudflare) режется на TLS-рукопожатии: ни
Python, ни curl не могут установить соединение. Это не приложение — так
ведёт себя сеть провайдера; обычно помогает VPN. Приложение при этом не
падает: показывает снимки и прежние копии с пометкой, а живые данные
подтянет, когда канал заработает. После двух обрывов подряд хост
считается недоступным три минуты (`net.HOST_PAUSE`), и все запросы к нему
отваливаются сразу — иначе каждая вкладка честно «считала» по несколько
минут, прежде чем сказать, что сети нет. Чего без живой базы не будет
совсем: разбора конкретного про-матча и сборки против конкретного драфта.

## Что умеет

**Драфт.** Выбираете героев противника, своих и забаненных. Приложение выдаёт
топ героев с разбивкой: сколько даёт контрпик, сколько — базовая сила героя
в выбранном ранге, и против кого именно герой хорош. Есть фильтр по позиции
(1–5) и рангу.
Матчапы берутся из одного из двух источников на выбор — OpenDota или STRATZ
(см. «Откуда данные»); со STRATZ добавляется колонка «Синергия» с уже
взятыми союзниками.

**Мета.** Таблица всех героев: винрейт и доля пиков в выбранном ранге,
про-пики, про-баны, про-винрейт.

**Турниры.** Пики, баны, спорность и винрейт каждого героя в турнирных
матчах за 1, 3 или 6 месяцев — по уровню турниров или по одному конкретному.
Считается напрямую по базе матчей OpenDota (`/explorer`): поля `pro_pick`
в справочнике героев почти пустые, а здесь — полторы тысячи матчей за квартал.

**Варды.** Тепловая карта обзорных вардов и стражей по турнирным матчам:
сторона, окно времени (до рога – 5, 5–10, 10–20, 20–35, 35+ минут),
герой, период, уровень турниров. Самые частые точки пронумерованы и
перечислены рядом с числом вардов и долей матчей. Источник — логи вардов
разобранных матчей в базе OpenDota (`obs_log` / `sen_log`: время от рога,
координаты в клетках карты 64..192); реплеи для этого не нужны. Картинка
карты лежит в сборке (`app/data/map_740.webp`, снята у OpenDota); если её
нет — качается один раз, а без неё рисуется схема.

**Про-матчи.** Лента последних профессиональных игр. По клику — порядок пиков
и банов обеих команд, статистика игроков, предметы каждого героя (стартовый
закуп, сборка с минутами покупки, итоговый инвентарь) и оценка, чей драфт был
удобнее по историческим матчапам. Матч грузится тремя короткими запросами
к базе OpenDota, а не одним JSON на 45 КБ: на слабых каналах большой ответ
обрывался и не доходил никогда.

В подборе турнирная статистика участвует как третья составляющая балла
с настраиваемым весом («приоритет» / «умеренно» / «не учитывать»).

**Подбор никогда не ждёт сеть.** Во время пика есть секунды, а сбор
турнирной статистики — несколько запросов к базе OpenDota по секундам
каждый (при её сбоях — минуты с повторами). Поэтому турнирная и личная
составляющие берутся из кэша, пусть и устаревшего, или из снимка
`app/data/tournament_fallback.json.gz`, а пересчёт уходит в фон. Если
данных нет вообще, подбор возвращается без этой составляющей с пометкой
«собирается в фоне», и таблица обновляется сама через несколько секунд.
Снимок обновляет CI по пятницам (`update-snapshots.yml`) или вручную:
`python3 app/tools/update_tournaments.py`.

**Чтение экрана.** Приложение само узнаёт героев на экране драфта и
подставляет их в драфт. Героя, выбранного вручную, оно не перезаписывает.
Галочка «Автоматически» включает слежение само на стадии выбора героев и
выключает после — по сигналу игры через Game State Integration (без него
авторежиму не на что опираться); настройки монитора и области берутся
последние выбранные, хранятся в `vision_settings.json` в папке данных.
Остановленное руками посреди драфта слежение авторежим не перезапускает.

## Чтение экрана

Нужны пакеты из `app/requirements-vision.txt` (на Windows их поставит
`start.bat`). Без них приложение работает как обычно, вкладка просто скажет,
чего не хватает.

Порядок работы:

1. Нажмите **«Скачать портреты»** — один раз качается 127 эталонов героев
   (около 9 МБ). Дальше сеть для распознавания не нужна.
2. Выберите монитор, область экрана и свою сторону (слева или справа).
3. **«Сканировать сейчас»** — разовый поиск, удобно проверить настройку.
4. **«Включить слежение»** — приложение будет опрашивать экран само.

### Как это устроено

Распознавание двухфазное, потому что честный полный поиск слишком медленный,
чтобы гонять его каждую секунду:

- **Калибровка** — поиск портретов по кадру в разных масштабах. Около
  3 секунд на верхней половине экрана, выполняется один раз за драфт.
  Масштаб подбирается по верхней полосе кадра, начиная с ожидаемой ширины
  портрета (6,4% ширины экрана при 16:9).
- **Слежение** — повторный поиск только при изменении полосы с портретами,
  в трёх масштабах вокруг известного.

Сравнивается только **верхняя часть портрета** (45%): в верхней полоске
Dota нижняя часть закрыта плашкой ранга и именем игрока, и с полным
эталоном на настоящем экране не находилось ничего. После уверенного
ряда пустые слоты между найденными героями досматриваются прицельно:
шаг между портретами одинаковый, и в слоте сравниваются все эталоны.
Так возвращаются герои, у которых лучшее совпадение по всему кадру пришлось
на мусор.

Проверено на настоящих скриншотах стадии выбора: 9 из 9 и 10 из 10 героев,
пустой слот (игрок ещё без героя) не подхватывается. Что отсекает
ложные срабатывания:

- **цвет** — сравнение идёт по цветной подписи, а не по градациям серого;
  плюс проверка насыщенности: портрет героя цветной, интерфейс и текст почти
  серые. Это оказалось решающим: без цвета на обычном рабочем столе стабильно
  «находились» три-четыре несуществующих героя;
- **геометрия** — портреты драфта стоят в один ряд, а ложные срабатывания
  разбросаны по кадру. Уверенность их не разделяет, геометрия разделяет;
- **минимальный размер** портрета относительно ширины экрана;
- **двойная проверка** — детекция принимается, только если поиск по шаблону
  и классификация цветной подписи назвали одного и того же героя.

### Роль с экрана

В рейтинге с выбором ролей игра подписывает роль под именем каждого игрока
вашей команды: «Лёгкая», «Центр», «Сложная», «Поддержка», «Полная
поддержка». Слежение читает эти подписи так же, как портреты, —
сопоставлением с эталонами (`app/data/roles/`, вырезаны из скриншота,
сжатого до ширины 1280; живой кадр перед поиском приводится к тому же
масштабу). OCR не нужен. Подпись «Поддержка» целиком входит в «Полная
поддержка», поэтому проверяется слово слева от неё.

Как это превращается в позицию («Авто» в списке «Позиция»):

1. Игра через GSI сообщает номер вашего слота в команде (`team_slot`),
   подпись под ним — ваша роль. Работает с первой секунды драфта, даже
   если вы пикаете первым.
2. Без GSI — роли слотов без портретов считаются свободными: когда
   очередь дошла до вас, пустой слот один.
3. Без подписей (обычный режим, другое разрешение) — по взятым союзникам:
   какие позиции по справочнику они закрыли, те заняты.

Соответствие: Лёгкая — 1, Центр — 2, Сложная — 3, Поддержка — 4, Полная
поддержка — 5. Проверено на двух сжатых скриншотах с разных сторон:
правильная подпись 0,82–0,87, лучшая чужая — 0,62. Вживую в полном
разрешении не проверено; если на экране игра не на весь монитор, слоты
считаются по порядку найденных подписей.

### Ограничения чтения экрана

- Проверено на двух скриншотах стадии выбора (1280×743 после сжатия
  мессенджером), на постороннем экране (ноль ложных срабатываний) и
  вживую на драфте у пользователя — герои находятся. Пороги распознавания
  собраны в начале `app/vision/recognize.py`.
- На экране выбора героя с сеткой всех героев при области «весь экран»
  находятся портреты из сетки — держите область «верхняя половина».
- Приложение не читает память игры и никак с ней не взаимодействует: оно
  просто смотрит на картинку экрана, как сторонний зритель.
- Сторона (свои или враги) определяется по положению портретов на экране,
  а не по данным игры. Если стороны определились наоборот — переключите
  «Моя сторона».

## Безопасно ли это для аккаунта

Приложение никак не вмешивается в игру, и это принципиально:

- **не читает и не пишет память процесса Dota** — именно это ловит VAC;
- **не внедряет ничего в игру** — ни DLL, ни хуков, ни оверлеев внутри процесса;
- **не нажимает ничего за вас** — никакого автопика и автоматизации ввода;
- **не меняет файлы игры**, кроме одного: конфига Game State Integration
  в папке `cfg/gamestate_integration/`, которая Valve создана именно для
  сторонних программ — так работают стримерские оверлеи и виджеты.

Что оно делает: смотрит на картинку экрана через системный API (как OBS
или Discord при демонстрации экрана), принимает JSON, который игра сама
шлёт по официальному механизму GSI, и ходит в публичный API OpenDota.

Гарантию может дать только Valve, но всё перечисленное — публичные и
официально поддерживаемые каналы, а не обход защиты.

## Свой герой и сборка

Приложение показывает стартовый закуп, порядок сборки по минутам,
ситуативные и итоговые предметы вашего героя — по агрегату турнирных матчей
за выбранный период. Считается одним запросом к базе OpenDota, ответ
единицы килобайт.

Кто ваш герой, узнаётся тремя способами, от лучшего к простому:

1. **Game State Integration** — два шага. Кнопка «Подключить игру» кладёт
   конфиг в папку Dota (или «Скачать конфиг» и положить вручную в
   `dota 2 beta\game\dota\cfg\gamestate_integration\`). И в Steam у Dota 2
   нужен параметр запуска **`-gamestateintegration`** (библиотека → Dota 2 →
   правый клик → Свойства → Параметры запуска) — без него игра папку
   с конфигами не читает вовсе. После перезапуска игра сама сообщает героя
   и сторону, сообщения идут уже из главного меню. Кнопка «Проверить
   подключение» показывает, на каком шаге затык. Проверено имитацией
   сообщения игры; вживую с Dota — нет.
2. **Кнопка «это я»** на распознанном союзнике.
3. **Выбор из списка** вручную.

## Мой аккаунт

Подбор учитывает, на ком вы сами играете лучше: личный винрейт на герое
относительно вашего общего, сжатый по числу игр, и опыт на герое — тот, кого
вы ни разу не брали, получает минус, основной герой — плюс. Вес переключается:
учитывать / приоритет / не учитывать.

Аккаунт задаётся ID, Steam64 или ссылкой на профиль OpenDota, Dotabuff,
steamcommunity.com/profiles. Если игра подключена через GSI, аккаунт
подхватывается сам. Нужна включённая в Steam «Открытая история матчей»,
иначе OpenDota об игроке ничего не знает — приложение об этом скажет.

## Откуда данные

**OpenDota API** — публичный, ключ не нужен. Ответы кэшируются в `app/.cache`,
чтобы не упираться в лимит 60 запросов в минуту.

### Снимки данных в репозитории

В `app/data/` лежат снимки, с которыми приложение работает **без обращений
к OpenDota**:

| Файл | Что | Обновить |
|---|---|---|
| `herostats_fallback.json.gz` | справочник героев, винрейты по рангам | `python3 app/tools/update_fallback.py` |
| `matchups_fallback.json.gz` | матчапы всех героев, 16 тысяч пар | `python3 app/tools/update_matchups.py` |
| `positions.json` | позиции героев из про-матчей | `python3 app/tools/update_positions.py` |
| `tournament_fallback.json.gz` | турнирная статистика героев за 1/3/6 мес | `python3 app/tools/update_tournaments.py` |
| `builds_fallback.json.gz` | сборки и прокачка всех героев по турнирам (3 мес, Premium + Professional) | `python3 app/tools/update_builds.py` |
| `wards_fallback.json.gz` | тепловая карта вардов: тип × сторона × окно времени, без фильтра по герою | `python3 app/tools/update_wards.py` |
| `map_740.webp` | картинка карты для вкладки «Варды» (снята у OpenDota) | вручную при смене карты |

Зачем это нужно: на некоторых каналах `api.opendota.com` отдаёт данные
со скоростью около 2 КБ/с — замерено на реальной машине. Один запрос стоил
20–40 секунд, а драфт из пяти врагов — минуты. Приложение выглядело зависшим.
А у одного из пользователей TLS-рукопожатие с OpenDota (она за Cloudflare)
рвётся вовсе — «SSL/TLS-соединение не установилось» и через Python, и через
curl. На таком канале живые запросы к базе не проходят никогда.

Порядок везде один: свежий кэш → устаревшая копия или снимок (мгновенно,
пересчёт уходит в фон) → и только если нет ничего, «считается». Это касается
матчапов, турнирной статистики (вкладка «Турниры», кнопка «Обновить» —
пересчитать сейчас), сборки и прокачки героя. Пока сервер досчитывает в
фоне, страница дозапрашивает сама; если OpenDota не отвечает, под данными
так и написано: «OpenDota не отвечает (причина), показан снимок от даты».
Сборка *против конкретного драфта* в снимке быть не может — она появляется,
только когда база отвечает. Три снимка (STRATZ, турниры, сборки) обновляет
CI по пятницам (`update-snapshots.yml`).

Снимки стоит пересобирать раз в патч.

### STRATZ — второй источник матчапов

| Файл | Что | Обновить |
|---|---|---|
| `stratz_fallback.json.gz` | матчапы и пары «вместе» по рангам, позиции героев | `STRATZ_TOKEN=… python3 app/tools/update_stratz.py` |

STRATZ не заменяет OpenDota, а дополняет подбор тем, чего у OpenDota нет:

- **матчапы по рангу** — четыре группы: Herald–Guardian, Crusader–Archon,
  Legend–Ancient, Divine–Immortal, плюс все ранги вместе;
- **синергия** — как герой выигрывает в одной команде с каждым другим.
  В подборе это третье слагаемое балла, колонка «Синергия», считается по
  уже взятым союзникам;
- **позиции по данным** — на какой позиции герой реально играет в этом ранге
  (порог: не меньше 10% его игр) и его винрейт на ней. С OpenDota фильтр
  по позиции идёт из ручного справочника `positions.json`, со STRATZ —
  из данных, и базовый винрейт берётся на выбранной позиции.

Чего у STRATZ **нет**: матчапов с разбивкой по позиции. Керри-Mirana и
саппорт-Mirana в матчапах по-прежнему одна Mirana.

Выборка на порядок больше, чем у OpenDota: у популярного героя сотни тысяч
игр в одном ранге за неделю, медиана по паре — тысячи игр против ~30. Снимок
суммирует последние три недели (недели у STRATZ идут с четверга). Побочный
эффект: сглаживание почти не сжимает такие выборки, и баллы со STRATZ
заметно крупнее, чем с OpenDota, — это не ошибка, а следствие того, что
данных хватает.

Ключ STRATZ пользователю **не нужен**: снимок лежит в репозитории, а
обновляет его GitHub Actions по пятницам (`update-snapshots.yml`) с токеном
из секретов репозитория, после чего пересобирает exe. Если задать свой токен
(переменная `STRATZ_TOKEN` или файл `stratz_token.txt` рядом с `start.bat`
или exe), приложение обновит снимок само в фоне, когда ему больше недели.

Две особенности API, из-за которых сделано именно так. Токен привязывается
к IP первого запроса: с VPN, который меняет адрес на каждом соединении,
живые запросы отвергаются — клиент держит одно соединение и переподключается,
пока не попадёт на нужный адрес, но со снимком этой проблемы просто нет.
И условия токена по умолчанию просят надпись «Powered by STRATZ» — она есть
под таблицей подбора.

Про **d2pt.com** (dota2protracker.com): автоматический сбор оттуда не делается
осознанно. В `robots.txt` сайта стоит `Disallow: /` для ClaudeBot, GPTBot,
CCBot и других агентов, а также сигнал `ai-train=no`. Сайт закрыт Cloudflare,
и большая часть данных доступна только по подписке.

## Как считается оценка

```
score(H) = W_MATCHUP * среднее(adv(H, e) по врагам e)
         + W_SYNERGY * среднее(syn(H, a) по союзникам a)     ← только со STRATZ
         + W_BASE * (winrate(H) − средний winrate)
```

`adv(H, e)` — насколько H лучше играет против e, чем e играет в среднем.
Берётся из таблицы матчапов e: если e против H побеждает реже обычного,
значит H его контрит. `syn(H, a)` — то же для пары в одной команде:
насколько a вместе с H выигрывает чаще, чем a в среднем. Сглаживается
так же, со своим K — разброс у синергий другой.

Веса и границы — в начале `app/scoring.py`.

### Почему среднее, а не сумма

Складывать пять матчапов — значит утверждать, что они независимы и
складываются один к одному. Это неверно и завышает оценку в разы.
На порядок героев среднее не влияет (делитель у всех одинаковый),
зато число остаётся интерпретируемым.

### Сглаживание

Матчапы OpenDota — это матчи лиг (их таблица `matches`): у популярного
героя около 3000 матчей в сумме по 126 соперникам, у редкого — 800. Отсюда
медиана всего ~30 игр на пару, а при n=30 разброс винрейта примерно
±9 процентных пунктов — сырое число почти ничего не значит.

Поэтому каждое преимущество умножается на `n / (n + K)`, где K оценивается
по самим данным (эмпирический байес):

```
Var(наблюдаемое) ≈ Var(истинное) + среднее(p(1-p)/n)
K = p(1-p) / Var(истинное)
```

На текущих данных получается разброс истинного эффекта около ±6 п.п. и K
в районе 50–70. Значение K показывается под таблицей рекомендаций: чем оно
больше, тем сильнее в данных шум.

Оценку DerSimonian–Laird здесь применять нельзя: объёмы выборок различаются
в сотни раз, её знаменатель вырождается, и она выдаёт разброс ±43 п.п.,
то есть заведомо абсурдный.

### Проверка на реальных матчах (бэктест)

```
python3 app/tools/backtest.py pub            # ранговые матчи после даты снимка STRATZ
python3 app/tools/backtest.py pro --months 3 # турнирные матчи
```

Скрипт берёт матчи с драфтами из базы OpenDota, считает преимущество
Radiant той же формулой, что и подбор, и сравнивает знак с исходом.
Ранговые матчи берутся только после даты снимка STRATZ — проверка вне
выборки. Результат на 20 000 ранговых матчей (снимок от 2026-09-14):

| Что в балле | Точность знака | AUC |
|---|---|---|
| «всегда Radiant» | 54.4% | 0.500 |
| матчапы STRATZ | 57.1% | 0.598 |
| только база (винрейт героя) | 54.2% | 0.558 |
| только синергия | 56.1% | 0.583 |
| матчапы + база 0.2 + синергия 0.5 (веса приложения) | 56.9% | 0.593 |
| матчапы + база 0.6 + синергия 1.0 (веса до 2026-09-16) | 56.6% | 0.588 |
| матчапы OpenDota | 50.7% | 0.510 |

Точность растёт с величиной преимущества: при |edge| до 1 п.п. — 53%,
1–2 — 60%, 2–3 — 62%, 3–5 — 71%. То есть балл не только угадывает
знак, но и его размер что-то значит. Картина одинакова во всех четырёх
рангах.

Выводы, которые из этого сделаны:

- матчапы OpenDota (матчи лиг) исход ранговых игр не предсказывают —
  поэтому STRATZ стоит источником по умолчанию;
- база и синергия дублируют силу героя, уже сидящую в матчапах, и с
  большим весом только портят оценку — веса снижены до 0.2 и 0.5;
- на турнирных матчах всё скромнее: STRATZ Divine–Immortal даёт 56.6%
  (AUC 0.58), драфты про заранее контрят друг друга. Матчапы OpenDota
  там показывают 71%, но это внутри выборки — они посчитаны по этим же
  матчам, и за прогноз это принимать нельзя.

## Чего приложение не умеет

- **Синергии с OpenDota.** Он не отдаёт винрейт пар героев в одной команде;
  с ним свои герои учитываются только как «эти уже заняты». Со STRATZ
  синергия есть.
- **Матчапов по позициям.** Керри Mirana и саппорт Mirana в матчапах — один
  и тот же герой у обоих источников. STRATZ даёт по позиции только базовый
  винрейт и сам факт, что герой на ней играет.
- **Ранга Immortal.** Поле `8_pick` у OpenDota сейчас пустое, поэтому Immortal
  в списке рангов не появляется. Если запросить ранг без данных через API,
  ответ честно откатится на «Все ранги» и вернёт поле `note` с пояснением.
- **Профессиональной меты как отдельного режима.** Полей `pro_pick`/`pro_win`
  хватает примерно на тысячу игр по всем героям — слишком мало.

## Структура

```
start.bat               запуск под Windows
app/
├── server.py           HTTP-сервер и маршруты API
├── window.py           собственное окно приложения (pywebview)
├── scoring.py          подбор героев, сглаживание, разбор драфта
├── net.py              HTTP-запросы с кэшем на диск
├── sources/
│   ├── base.py         интерфейс источника данных
│   ├── opendota.py     реализация для OpenDota
│   ├── stratz.py       снимок STRATZ: матчапы по рангам, синергии, позиции
│   └── __init__.py     выбор активного источника
├── vision/
│   ├── icons.py        скачивание эталонных портретов
│   ├── capture.py      захват экрана (Windows, macOS, Linux)
│   ├── recognize.py    поиск и классификация героев
│   └── watcher.py      фоновое слежение за экраном
├── assets/heroes/      эталонные портреты (качаются при первом запуске)
└── web/                интерфейс: index.html, app.js, styles.css
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/heroes` | справочник героев и доступные ранги |
| POST | `/api/recommend` | подбор против драфта |
| GET | `/api/meta?bracket=&role=` | таблица меты |
| GET | `/api/pro/matches` | лента про-матчей |
| GET | `/api/pro/match?id=` | разбор матча |
| GET | `/api/cache/clear` | сбросить кэш |
| GET | `/api/vision/status` | доступно ли чтение экрана, мониторы, эталоны |
| GET | `/api/vision/state` | что сейчас видно на экране |
| POST | `/api/vision/icons` | скачать эталонные портреты |
| POST | `/api/vision/config` | монитор, область, интервал опроса |
| POST | `/api/vision/scan` | разовый поиск героев на экране |
| POST | `/api/vision/start` · `/stop` | включить и выключить слежение |

Пример запроса подбора:

```
curl -X POST http://127.0.0.1:8777/api/recommend \
  -H 'Content-Type: application/json' \
  -d '{"enemy":[1,8,44],"bracket":"7","limit":10}'
```
